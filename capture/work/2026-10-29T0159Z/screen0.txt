API 单价，会错过很大一部分真实成本结构。同样一个 Sonnet 5 工作负载，最终账单可能因为上下文是否被缓存，以及结果是否必须同步返回，而出现很大差异。\n \n \n第六部分 - 长上下文，是一个便宜工作流悄悄变贵的地方\n下一个成本问题通常会在 Agent 已经运行一段时间之后出现。\n一段最开始只有很短 Prompt 的对话，会逐渐积累终端日志、代码、工具输出、之前犯过的错误、浏览器结果以及大量文档。现代模型可以接受巨大的上下文，因此最简单的实现方式就是不断把所有东西一起往后带。\n模型能够接受巨大上下文，并不意味着每一次请求都应该使用它。\nGrok 4.6 是一个很好的例子。当 Prompt 低于 200,000 Token 时，它的价格是每百万输入 Token 2 美元、缓存输入 0.50 美元、输出 6 美元。一旦 Prompt 达到 200,000 Token，它的长上下文价格变成 4 美元、1 美元和 12 美元。xAI 明确说明，一旦跨过这个门槛，长上下文价格将应用于整个请求里的所有 Token。\nGPT-5.6 也有自己的门槛。OpenAI 表示，当 Prompt 超过 272,000 个输入 Token 时，整个请求的输入价格会变成 2 倍，输出价格变成 1.5 倍。\n这产生了一个有些奇怪的激励：供应商正在竞争谁能提供更大的上下文窗口，而高效用户反而需要越来越谨慎地选择，到底应该把什么放进这些窗口里。\n当任务确实需要时，100 万 Token 的上下文非常有价值。但如果一个 Agent 只是因为没人决定清理，而一直拖着 40 分钟前早已过时的终端输出继续运行，那么这种长上下文就会变得非常昂贵。\n因此，长期运行的 Agent 需要某种形式的记忆管理纪律。旧交互可以被压缩。稳定材料可以被缓存。大型文档集合可以在相关时再检索，而不是永久附加。日志可以被总结。已经完成作用的工具结果可以从活跃 Prompt 中移除。\n这没有选择最新的前沿模型那么吸引眼球，但它对账单的影响可能更大。\n一个上下文管理糟糕、不断重复携带巨大历史的便宜模型，完全可能比一个经过仔细路由的昂贵模型更贵。\n \n第七部分 - 下一笔节省，来自不再让最强的模型处理最简单的工作\n订阅习惯在 API 这边也有一个对应版本：一旦有人选定了最喜欢的前沿模型，就会把所有事情都发给它。\n困难的架构决策？前沿模型。\n从文档里提取日期和发票编号？还是同一个模型。\n调试 race condition？还是同一个模型。\n把 20,000 条商品记录转换成固定 JSON 格式？还是同一个模型。\n这样做很方便，因为只需要维护一个系统。但如果是处理大量常规任务，这也是一种非常昂贵的方式。\n当前 OpenAI 的价格很能说明这个数量级。GPT-5.6 Sol 每百万输入 Token 4 美元、每百万输出 Token 20 美元。GPT-5.6 Luna 则是 0.20 美元和 1.20 美元。输入价格相差 20 倍，输出价格大约相差 16 倍。\n这绝不意味着 Luna 和 Sol 可以互换。它们本来就是刻意区分的不同档位。真正有用的结论是：如果一个工作流里有 20 种不同类型的任务，大概率没有必要把这 20 种任务全部分配给同一个模型档位。\n提取、分类、格式化、基础总结、直接转换和第一轮筛选，都可以先在便宜模型上测试。困难情况再升级到更强的模型。一个 Coding Workflow 可以把最昂贵的推理留给架构设计、困难调试或者模糊的代码审查，同时把重复性操作路由到别处。\n这样一来，真正重要的成本指标就变成了 每一件成功完成的工作需要多少钱，而不是每个 Token 多少钱。\n一个便宜十倍的模型，如果需要四次重试和人工修复，最终反而可能输掉这场比较。一个前沿模型如果一次就能解决任务，可能才是更便宜的选择。唯一能知道答案的方法，是测量整个工作流，而不是盯着价格表。\n所以，我不会建议围绕“哪个模型最便宜？”这个问题搭建个人 AI 工具栈。\n更好的问题是：“我的哪些工作，一旦换到低一个档位的模型，质量才会真正变差？”\n这个实验可能比取消一个 20 美元订阅省下更多钱。\n \n第八部分 - 在改任何东西之前，先做一次 30 天审计\n大多数人不需要复杂的 Token Dashboard 才能找到明显的浪费。他们真正需要的，只是认真观察一个月。\n对于每一个订阅，简单记录你大概多久打开一次，以及你从中需要什么。区分产品功能和模型访问，比精确统计 Prompt 数量更重要。如果你反复使用 Claude Code、Grok Bot、Cursor 使用量。也可能发现完全相反的情况：API 计费器三天就跑到了 25 美元，这时原来的订阅反而显得非常合理。\n两种结果都有价值，因为你终于开始把价格和自己的真实行为进行比较。\n同样的审计也应该寻找技术层面的浪费。如果一个巨大的稳定 Prompt 出现在 Agent 的每一轮调用中，测试缓存。如果任务可以隔夜完成，测试 Batch。如果上下文经常跨过 200K 或 272K 产品，是保持访问最佳模型的一种简单方式。现在，市场已经复杂得多。\n模型访问正在不同产品之间扩散。Cursor 现在包含 Grok Bot。API 可以直接提供前沿模型和廉价模型档位。提示词缓存可以大幅降低重复输入的价格。批处理可以把异步 Claude 工作负载的成本砍半。巨大的上下文窗口带来了自己的价格门槛。便宜模型也已经足够强，可以吸收越来越多的常规工作。\n因此，高效的个人 AI
